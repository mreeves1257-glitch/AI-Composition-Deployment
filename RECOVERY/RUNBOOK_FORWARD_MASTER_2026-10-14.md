## Execution order

1. Reassemble and verify the 3.48 GB production master:
   python RECOVERY/reassemble_production_master.py <production_parts> <work>/production

2. Reconstruct and verify replacement libraries:
   python RECOVERY/recover_replacement_resources.py <resource_artifacts> <work>/resources

3. Read-only audit the R1/R2 repair packages:
   python RECOVERY/audit_repair_packages.py <repair_dir> <work>/repair_audit.json

4. Extract the verified production master into an isolated working copy. Never edit the source ZIP.

5. Generate candidate repair mapping:
   python RECOVERY/generate_candidate_repair_map.py <isolated_working_copy> <repair_dir> <work>/candidate_repair_map.json

6. Review every repair member against the audit, R1/R2 records, and intended forward changes.
   - No basename-only candidate is automatically trusted.
   - Set reviewed=true only after exact target paths are confirmed.
   - Preserve old source/status entries when the lineage requires history.
   - Do not delete existing Composer content simply because a repair package does not mention it.

7. Apply only the reviewed repair map through:
   python RECOVERY/run_forward_recovery.py --production-parts <production_parts> --resource-artifacts <resource_artifacts> --repair-dir <repair_dir> --work <work> --repair-map <reviewed_map>

8. Run functional audio verification:
   python RECOVERY/verify_forward_composer.py <isolated_forward_working_copy> <verification_dir>/FORWARD_FUNCTIONAL_VERIFICATION.json
   Required: exactly 55 genre profiles and 55 finished non-silent WAVs at 440 Hz plus 55 finished non-silent WAVs at 432 Hz.

9. Run regression gates:
   python RECOVERY/run_regression_gates.py <isolated_forward_working_copy> <verification_dir>/REGRESSION_VERIFICATION.json
   Required: Classical subsystem exactly 43 tests, separately counted from the 55 genres, plus full unittest discovery PASS.

10. Package only after all gates PASS:
   python RECOVERY/package_verified_forward_master.py <isolated_forward_working_copy> <verification_dir> <master_output>
   Default candidate name:
   AI_Composer_FORWARD_MASTER_55_GENRES_440_432_TUNING_2026-10-14_R3.zip

11. Verify archive CRC, full SHA-256, member count, and certification sidecar generated by the packager.

12. Split the exact verified archive into sub-512-MiB persistent parts:
   python RECOVERY/split_verified_master.py <master_zip> <split_output>

13. Save every split part plus split manifest and verification JSON into persistent Library storage.

14. Independently materialize the saved pieces and reassemble them once more. Verify the reassembled SHA-256 equals the packaged master's SHA-256.

15. Only after step 14 succeeds may the new R3 archive be called the active forward master.
